# Работа при недоступности провайдера

Этот документ описывает одну [Capability][CAPABILITY-TERM].

Способность продукта продолжать обслуживать ИС, когда провайдер недоступен, отдавая ранее полученные данные из кэша там, где это разрешено политикой, и явно сообщая об их устаревании.

## Ключевые сценарии

[Ключевые сценарии][KEY-SCENARIO-TERM] — stakeholder stories; не user stories и не [реквест][REQUEST-TERM].

### Бизнес-операции не останавливаются

**Сценарий:** [Владелец ИС][SH-03] продолжает выполнять бизнес-операции во время даунтайма провайдера, получая последние известные данные из кэша, если политика эндпоинта это допускает.

**Инструменты:** отдача устаревшего ответа при недоступности провайдера.

**Outcome:** даунтайм провайдера не превращается в даунтайм всех ИС организации.

### Устаревшие данные распознаются

**Сценарий:** [Владелец ИС][SH-03] всегда отличает устаревший ответ от актуального и знает его возраст, чтобы сама ИС решила, можно ли на него опираться в данной операции.

**Инструменты:** явная пометка устаревшего ответа и его возраста.

**Outcome:** ИС не принимает устаревшие данные за актуальные.

### Политика по эндпоинтам

**Сценарий:** [Администратор продукта][SH-04] разрешает отдачу устаревших данных только для эндпоинтов, где это безопасно для бизнеса, и ограничивает допустимый возраст данных.

**Инструменты:** политика деградации провайдера и эндпоинта: разрешено ли, предельный возраст.

**Outcome:** устойчивость не достигается ценой недопустимо старых данных.

## Границы

### Входит

- Определение недоступности провайдера для обслуживания обращения.
- Отдача устаревших ответов по политике с явной пометкой.
- Явный отказ, если устаревшего ответа нет или политика запрещает его отдачу.

### Не входит

- Кэширование в обычном режиме — [CAP03-02](CAP03-02-response-caching.md).
- Мониторинг и оповещения о состоянии провайдера — `CAP06-01`.

## Инварианты и углубление

### Инварианты (меняются редко по смыслу)

- Устаревший ответ никогда не отдаётся без явной пометки.
- Устаревший ответ отдаётся только при недоступности провайдера и только если это разрешает политика.
- Устаревший ответ не расходует лимит и фиксируется в учёте отдельным исходом.

### Допустимое углубление (меняется чаще)

- Переключение на резервный контракт или ключ провайдера при отказе основного.
- Возможность ИС явно запросить «только актуальные данные».

## Открытые вопросы

- По каким признакам продукт считает провайдера недоступным: ошибки, таймауты, состояние из мониторинга `CAP06-01`.
