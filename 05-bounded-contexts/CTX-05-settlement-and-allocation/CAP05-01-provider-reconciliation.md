# Сверка с провайдером

Этот документ описывает одну [Capability][CAPABILITY-TERM].

Способность продукта быть источником данных для сверки взаиморасчётов с провайдером за отчётный период.

## Ключевые сценарии

[Ключевые сценарии][KEY-SCENARIO-TERM] — stakeholder stories; не user stories и не [реквест][REQUEST-TERM].

### Сверка по собственным данным

**Сценарий:** [Ответственный за договор][SH-05] по закрытии периода получает потребление по контракту, посчитанное по правилам провайдера, и сверяет с ним акт провайдера, не принимая данные провайдера на веру.

**Инструменты:** итог потребления по контракту за закрытый период, сопоставление с актом провайдера.

**Outcome:** организация подписывает акт по своим данным или обоснованно его оспаривает.

### Объяснение расхождений

**Сценарий:** [Ответственный за договор][SH-05] при расхождении с актом видит, на каких днях, эндпоинтах и исходах обращений оно возникло, и предъявляет провайдеру обоснование.

**Инструменты:** детализация потребления периода до фактов обращений.

**Outcome:** расхождение объясняется или превращается в конкретную претензию.

### Обнаружение обращений в обход

**Сценарий:** [Финансовая служба][SH-01] видит, что провайдер насчитал больше, чем прошло через продукт, и узнаёт о потреблении контракта в обход продукта.

**Инструменты:** сверка общего объёма по контракту с актом провайдера.

**Outcome:** обход продукта не остаётся незамеченным.

## Границы

### Входит

- Итоги потребления по контракту за закрытый период.
- Сопоставление с актом провайдера и детализация расхождений.
- Корректировки закрытых периодов по итогам сверки.

### Не входит

- Подсчёт потребления — `CAP04-01`.
- Распределение по подразделениям — [CAP05-02](CAP05-02-consumption-allocation-report.md).
- Денежные расчёты с провайдером.

## Инварианты и углубление

### Инварианты (меняются редко по смыслу)

- Итоги закрытого периода не меняются без явной корректировки, которая сохраняется в истории.
- Итог сверки выводится из тех же фактов учёта, что и распределение по подразделениям.

### Допустимое углубление (меняется чаще)

- Загрузка акта провайдера в машиночитаемом виде и автоматическое сопоставление.
- Получение данных о потреблении от провайдера по его интерфейсу, если он есть.

## Открытые вопросы

- Порядок действий при подтверждённом расхождении: корректировка учёта продукта, корректировка распределения по подразделениям или только претензия провайдеру.
- Как распределять между подразделениями потребление, которое провайдер насчитал, а продукт не видел.
