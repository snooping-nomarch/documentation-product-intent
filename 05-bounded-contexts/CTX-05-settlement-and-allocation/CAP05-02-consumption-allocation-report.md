# Распределение потребления за период

Этот документ описывает одну [Capability][CAPABILITY-TERM].

Способность продукта по итогам отчётного периода дать фактическое распределение потребления провайдеров по внутренним ключам и подразделениям для аллокации затрат.

## Ключевые сценарии

[Ключевые сценарии][KEY-SCENARIO-TERM] — stakeholder stories; не user stories и не [реквест][REQUEST-TERM].

### Аллокация затрат по факту

**Сценарий:** [Финансовая служба][SH-01] по закрытии периода получает доли каждого подразделения и ИС в потреблении каждого контракта и распределяет затраты на провайдера по факту, а не по оценке.

**Инструменты:** отчёт о распределении потребления за закрытый период по ключам и ветвям структуры подразделений.

**Outcome:** аллокация затрат обоснована и воспроизводима при проверке.

### Подразделение платит за своё

**Сценарий:** [Руководитель подразделения][SH-02] видит, что подразделению отнесено только потребление его ИС по запросам к провайдеру, без ответов из кэша и без чужого потребления.

**Инструменты:** распределение только тарифицируемых фактов, атрибутированных ключам подразделения на момент потребления.

**Outcome:** споры о распределении затрат решаются по данным.

## Границы

### Входит

- Распределение потребления контракта за закрытый период по ключам и подразделениям в единицах потребления.
- Агрегация по дереву подразделений.
- Выгрузка распределения во внешние финансовые системы.

### Не входит

- Цены и суммы в деньгах — вне продукта.
- Сверка с провайдером — [CAP05-01](CAP05-01-provider-reconciliation.md).
- Аналитика произвольных периодов — `CAP04-02`.

## Инварианты и углубление

### Инварианты (меняются редко по смыслу)

- Сумма распределения за период равна итогу потребления по контракту за этот период.
- Распределение использует структуру подразделений, действовавшую на момент потребления.
- Ответы из кэша не распределяются.

### Допустимое углубление (меняется чаще)

- Дополнительные разрезы распределения (центры затрат, проекты).
- Перевод в деньги по тарифам контракта как отдельное углубление, если замысел это примет.

## Открытые вопросы

- В каком разрезе нужен отчёт, если у одной ИС несколько внутренних ключей: по ключу, по ИС или по обоим.
- Как распределять потребление, относящееся к общему объёму контракта, а не к отдельным обращениям (например, абонентская часть).
