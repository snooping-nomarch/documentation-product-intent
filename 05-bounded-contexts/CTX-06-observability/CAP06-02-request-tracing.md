# Трассировка обращений

Этот документ описывает одну [Capability][CAPABILITY-TERM].

Способность продукта восстановить путь любого обращения ИС через продукт до провайдера и связать его с трассировкой в самой ИС.

## Ключевые сценарии

[Ключевые сценарии][KEY-SCENARIO-TERM] — stakeholder stories; не user stories и не [реквест][REQUEST-TERM].

### Что случилось с запросом

**Сценарий:** [Владелец ИС][SH-03] по идентификатору своего запроса узнаёт, что с ним сделал продукт: ответил из кэша, отказал (и почему) или передал провайдеру, и что ответил провайдер.

**Инструменты:** трасса обращения с решением продукта и ответом провайдера.

**Outcome:** разбор инцидента по конкретному запросу занимает минуты.

### Сквозная трасса

**Сценарий:** [Администратор продукта][SH-04] видит обращение к провайдеру как часть сквозной трассы бизнес-операции ИС, если ИС передаёт свой контекст трассировки.

**Инструменты:** приём и продолжение контекста трассировки ИС, передача трасс во внешние системы трассировки.

**Outcome:** продукт не разрывает трассу бизнес-операции.

## Границы

### Входит

- Трасса каждого обращения: поступление, проверки, решение продукта, запрос к провайдеру, ответ.
- Связь с контекстом трассировки ИС.
- Поиск трасс по ключу, времени, исходу и идентификатору запроса ИС.

### Не входит

- Агрегированные показатели и оповещения — [CAP06-01](CAP06-01-provider-health-monitoring.md).
- Факты учёта для финансов — `CAP04-01`.

## Инварианты и углубление

### Инварианты (меняются редко по смыслу)

- Трасса не содержит ключей провайдера и чувствительных данных в открытом виде ([QA-05](../../04-quality-attributes/QA-05-secret-and-data-protection.md)).
- Трассировка не замедляет обслуживание обращений ([QA-03](../../04-quality-attributes/QA-03-latency-overhead.md)).

### Допустимое углубление (меняется чаще)

- Выборочное сохранение содержимого запросов и ответов для разбора, по политике ИБ.

## Открытые вопросы

- Сколько хранить трассы и нужна ли выборка (сэмплирование) при большом потоке обращений.
